# V2 G2 — PostgreSQL/pgvector migration and Compose receipt

| 항목 | 값 |
|---|---|
| 날짜 | 2026-07-30 (Asia/Seoul) |
| 상태 | `PARTIAL` — G2 infrastructure verified; G3 product runtime not claimed |
| 범위 | PostgreSQL+pgvector schema, immutable migration runner, Compose DB/migration/test topology |
| 비범위 | CorpusStore product path, ingestion/retrieval/cache invalidation behavior, FastAPI wiring, Codex/SSE live smoke |

## Why → What → How → Trade-off → 배운 점

- **Why**: V1 SQLite metadata/cache와 Chroma vector는 cross-store transaction이
  없다. G3의 atomic CorpusStore 전에 schema/migration fail-closed 경계를 만든다.
- **What**: PostgreSQL 17.10 + pgvector 0.8.6, `vector(384)` schema, Psycopg 3
  runner와 digest-pinned Compose를 추가했다.
- **How**: advisory lock, SHA-256 ledger, history prefix 검사, migration별 rollback,
  healthy dependency와 temporary test DB로 검증했다.
- **Trade-off**: immutable migration과 Docker 운영비가 추가된다. extension 설치
  권한·vendor support·HA/PITR·제품 API 통합은 별도 책임이다.
- **배운 점**: checksum match는 history 정상성을 뜻하지 않으며, `depends_on`만으로
  DB readiness를 뜻하지 않는다.

## 실제 실행 영수증

### Runtime

```sh
docker compose up -d --wait db
docker compose run --rm migrate officeagent-migrate
docker compose run --rm migrate officeagent-migrate --check
```

최초 apply의 sanitized JSON:

```json
{
  "already_applied": [],
  "applied_now": ["0001"],
  "migration_head": "0001",
  "server_version": "17.10 (Debian 17.10-1.pgdg12+1)",
  "vector_version": "0.8.6"
}
```

재검사는 `already_applied=["0001"]`, `applied_now=[]`를 반환했다. DB는 healthy,
port는 `127.0.0.1:15432`로만 publish됐다. ledger는
`0001|1a82dfde98ea0e5f0f7502c117cf39a8657e04321ac15c3cead4d44411bedc`이며,
통합 테스트 뒤 `officeagent_test_%` database는 남지 않았다.

### Automated tests와 package

```sh
docker compose run --rm test
```

결과: **33 passed in 5.76s**. first apply/rerun, checksum drift fail-closed,
failed SQL rollback, non-prefix history fail-before-apply, advisory-lock serialization을
포함한다. 이 수치는 G3 제품 동작을 뜻하지 않는다.

```sh
uv run --frozen pytest -q
uv run --frozen ruff check .
uv lock --check
docker compose config --quiet
git diff --check
```

결과: host suite `27 passed, 6 skipped`, Ruff/lock/Compose config/diff check PASS.
DB admin URL이 필요한 migration test는 host에서 skip하고 Docker test service에서만
실행한다. wheel audit는 `officeagent/migrations/0001_v2_schema.sql` 포함을 확인했다.

Windows host의 generated `officeagent-migrate` shim은 local Application Control
policy(os error 4551)로 차단됐다. 같은 코드는 다음 module path로 확인했고 Linux
Compose console-script path는 위 명령으로 실제 검증했다.

```powershell
uv run --frozen python -m officeagent.infrastructure.migrations --check
```
