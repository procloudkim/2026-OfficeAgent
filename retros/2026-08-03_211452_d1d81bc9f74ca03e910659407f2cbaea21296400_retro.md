### Keep (좋았던 것)

- 빠른 진입 경로와 상세 실행 절차, 상태 정본을 분리해 평가 순서를 재구성해야 하는 부담과 정보 불일치 위험을 함께 줄였다.
- 문서별 독자와 역할을 명시해 같은 설명을 중복하지 않고 필요한 정보로 이동할 수 있게 했다.
- 문서 전용 변경과 실제 런타임 재검증을 구분해 검증 이력이 과장되어 보이는 문제를 예방했다.

- 평가자가 새 문서 경로만으로 전체 절차를 막힘없이 수행할 수 있는지는 아직 증명되지 않았다.

> 최종 내용 책임: 지원자 / 사실 대조·초안·문장 정리: Codex 보조

- 처음 보는 평가자가 README의 명령을 실행하려면 사전 조건, 정상 출력, 오류 해석과

  `EVALUATOR_MANUAL=상세 runbook`, `V2_REQUIREMENTS_TRACEABILITY=상태·증거 정본`,
  `ARCHITECTURE·ADR=선택 이유`로 분리했다.
- 같은 테스트 수와 PASS 문장을 모든 문서에 복사하지 않았다. 실행 수치는
  Traceability 한 곳에서 관리하고 다른 문서는 exit code와 링크를 제공해 문서 drift
  가능성을 줄였다.
- 매뉴얼의 각 절차는 `목적→사전 조건→명령→예상 결과→증명하지 않는 것→실패 처리`
  순서를 따른다. Docker 검증과 실제 Codex 검증을 분리해 구독·credential이 없는
  평가자도 첫 경로를 완료할 수 있게 했다.
- 실제 Codex live 결과는 structured runtime anchor `c42e7c9`에 귀속한다. 이후
  docs-only HEAD는 runtime path 동등성과 문서·remote 검사를 통과해야 하지만, 이를
  최종 HEAD에서 live를 새로 실행했다는 뜻으로 표현하지 않는다.
- 원본 PRD와 과거 자동 KPT는 생성 시점 기록이므로 현재 매뉴얼처럼 덮어쓰지 않았다.
  현재 사실과 충돌하면 Traceability와 code/test를 우선한다.
- 면접에서는 “문서를 많이 썼다”가 아니라, 평가자의 탐색 비용과 중복 상태의 drift를
  줄이기 위해 문서별 단일 책임과 증거 귀속을 설계했다고 설명한다.
