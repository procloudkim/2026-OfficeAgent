- 실행 안내서에 승인 점검, 지표 규칙, 전체 분할 실행, 잔여 데이터 경고와 종료 코드 경계를 추가했다.

## KPT 회고

### Keep (좋았던 것)

- 정확한 바이트와 사람 승인을 결합한 버전형 기준선을 먼저 만들어 기본값 변경 전 품질 판단의 근거를 분리했다.
- 각 분할에 검색 음성 사례를 포함해 답변 가능한 성공 사례뿐 아니라 근거 없는 응답 회피도 측정할 수 있게 했다.
- 원격 대상과 제품 데이터베이스, 잘못된 분할을 차단해 평가 실행이 의도하지 않은 환경에 영향을 주지 않도록 했다.
- 냉독에서 발견한 승인 형식과 예외 정보 노출 문제를 실패 테스트로 재현해 시간대 검증과 정제된 종료 코드로 보완했다.
- 지표의 의미를 파일 순위와 별칭 포함 검사 및 엄격한 회피 조건으로 한정해 과도한 의미론적 성능 주장을 피했다.

### Problem (나빴던 것)

- 실제 임베딩, 데이터베이스, 외부 평가기를 결합한 평가는 실행하지 않아 실제 경로의 동작이 아직 증명되지 않았다.
- 데이터셋 승인이 대기 상태여서 승인 필수 실행의 증거가 없다.
- 선택된 합성 질문과 검색 문맥의 외부 전송에는 별도 실행 승인과 사용자 데이터셋 채택이 필요하다.
- 공개된 절차 보류 분할은 맹검 벤치마크가 아니므로 일반화나 성능 우위를 증명하지 못한다.
- 제품의 분할 크기와 임계값은 변경하거나 검증하지 않았다.

### Try (개선해야 할 것)

- 사용자 데이터셋 채택과 외부 전송 승인을 받은 뒤 데이터셋 승인을 확정한다.
- 승인된 데이터셋으로 승인 필수 옵션을 사용해 실제 임베딩, 데이터베이스, 외부 평가기 경로를 실행한다.
- 실제 실행에서 생성된 결과와 종료 코드를 보존해 승인 필수 평가의 재현 가능한 증거를 남긴다.
- 공개 분할과 분리된 추가 평가 자료를 마련해 일반화 판단의 독립성을 높인다.
- 승인된 평가 결과가 확보된 뒤에만 제품 분할 크기와 임계값 변경 여부를 검토한다.
