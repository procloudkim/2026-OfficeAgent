## KPT 회고

### Keep (좋았던 것)

- 공식 App Server에서 실제 토큰 델타 14개를 수신해 통합 경로를 선택한 점이 좋았다. 진행 이벤트와 실제 답변 토큰 스트리밍을 구분해 기술 선택의 근거를 확보했다.
- Retrobot 입력을 최신 커밋과 명시적인 작업 로그로 제한한 점이 효과적이었다. 회고에 불필요한 다른 프로젝트 정보나 민감정보가 유입될 범위를 줄였다.
- 훅을 일반 커밋과 자동 회고 커밋으로 나누어 확인한 점이 좋았다. 자동 생성뿐 아니라 재귀 중단까지 실제 커밋 흐름에서 검증했다.
- 이메일 재작성 전에 복구용 ref를 만들고 커밋별 불변 항목을 비교한 점이 효과적이었다. 이력 수정 과정에서 의도하지 않은 변경을 탐지할 근거를 남겼다.
- 시간대 오류의 원인을 Windows Git Bash 환경으로 좁히고 POSIX 시간대 문자열로 수정해 회고 파일명과 타임라인의 9시간 차이를 바로잡았다.

### Problem (나빴던 것)

- 자동화 테스트가 health 경로 1개만 다루므로 ingestion, retrieval, 캐시 무효화 동작은 아직 증명되지 않았다.
- 실제 애플리케이션 구현이 아직 없어 핵심 기능 완성을 주장할 수 없다.
- 이메일을 재작성한 커밋의 push와 원격 `main`·로컬 `main` SHA 일치는 아직 확인되지 않았다.
- 템플릿의 `codex --quiet`는 현재 Codex CLI에서 지원되지 않아 exit 2로 실패했다.
- `TZ=Asia/Seoul`이 Windows Git Bash에서 UTC로 처리되어 기존 회고 기록에 9시간 오차가 발생했다.

### Try (개선해야 할 것)

- ingestion, retrieval, 캐시 무효화 각각에 대해 실패하는 테스트를 먼저 작성하고 구현 후 회귀 검증을 수행한다.
- 구독 없이 실행 가능한 health 테스트와 `uv lock` 검증 범위를 유지하면서 실제 애플리케이션 경로로 테스트 범위를 확장한다.
- 재작성된 커밋을 push한 뒤 원격 `main`과 로컬 `main`의 SHA를 직접 비교해 이력 동기화를 확인한다.
- 훅에서 사용하는 Codex 명령과 이벤트 계약을 현재 CLI 및 App Server 인터페이스에 맞춰 고정하고 실패 시 진단 가능한 결과를 남긴다.
- Windows Git 환경의 시간대와 재귀 방지 조건을 자동 테스트에 포함해 동일한 오류의 재발을 막는다.
