## KPT 회고

### Keep (좋았던 것)

- 공식 문서와 현재 CLI 동작을 직접 대조해 지원되지 않는 `codex --quiet` 경로를 조기에 제거했다. 덕분에 실제 토큰 델타를 제공하는 App Server 경로로 전환할 수 있었다.
- Retrobot의 입력 범위를 최신 커밋과 명시적인 `WORKLOG`로 제한했다. 다른 프로젝트 정보나 민감정보가 회고에 섞일 위험을 줄이는 데 효과적이었다.
- 일반 커밋과 자동 회고 커밋을 실제로 연속 생성해 훅 실행과 재귀 방지를 확인했다. 설정 확인에 그치지 않고 자동화의 핵심 동작을 검증했다.
- 시간대 오류의 원인을 Windows Git Bash의 `TZ` 해석 차이로 좁히고 기존 기록까지 정정해 회고 파일명과 타임라인의 일관성을 회복했다.

### Problem (나빴던 것)

- `TZ=Asia/Seoul`이 Windows Git Bash에서 기대대로 동작하지 않아 회고 기록이 9시간 어긋났다.
- 기존 재귀 방지 조건이 너무 넓어 제목에 Retrobot이 포함된 일반 커밋도 건너뛸 수 있었다.
- 자동화 테스트는 health 경로 1개만 다루며 ingestion, retrieval, 캐시 무효화는 아직 검증하지 못했다.
- 실제 애플리케이션 구현과 전체 동작은 아직 완료 또는 검증됐다고 볼 근거가 없다.
