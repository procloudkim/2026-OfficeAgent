## KPT 회고

### Keep (좋았던 것)

- migration checksum뿐 아니라 적용 이력의 forward-prefix를 먼저 검사해 과거 migration 누락이나 비정상 backfill을 적용 전에 차단하도록 설계했다.
- migration별 transaction과 실패 SQL rollback 테스트를 함께 두어 스키마 변경 실패가 부분 적용으로 남을 위험을 줄였다.
- Compose에 동일한 DB 이미지, extension과 readiness 조건을 고정해 evaluator와 CI가 구독 없이 같은 검증 경로를 재현할 수 있게 했다.
- advisory-lock serialization을 테스트해 동시에 실행되는 migration의 경합을 명시적인 검증 대상으로 만들었다.
- 측정되지 않은 성능이나 enterprise SLA를 주장하지 않고, 이번 커밋의 증거 범위를 migration·Compose 기반으로 제한했다.

### Problem (나빴던 것)

- 초기 Compose 구성에서 host port `55432` 충돌, 존재하지 않는 uv bookworm 태그, 잘못된 `--check` 명령과 누락된 `.githooks`가 발견됐다.
- host 테스트에서는 관리자 DB URL을 제공하지 않아 PostgreSQL 관련 6개 테스트가 skip됐다.
- G3 CorpusStore transaction과 retrieval, cache invalidation은 아직 구현하거나 검증하지 않았다.
- concurrent ingest/query, FastAPI wiring, Codex 호출과 SSE live smoke도 이번 게이트의 검증 범위에 포함되지 않았다.
- PostgreSQL·pgvector 전환이 실제 한국어 검색 품질이나 성능을 개선한다는 증거는 아직 없다.

### Try (개선해야 할 것)

- Compose와 CI 입력을 사전 검사해 이미지 태그, 포트, build context와 실행 명령 오류를 더 이른 단계에서 발견한다.
- G3에서는 unified CorpusStore의 rollback과 동시성 실패 테스트를 먼저 작성한 뒤 구현한다.
- document, chunk/vector, cache invalidation과 corpus revision이 하나의 transaction에서 함께 commit 또는 rollback되는지 검증한다.
- concurrent ingest/query와 stale recache 경계를 재현하는 통합 테스트를 추가한다.
- 저장소 전환 후 FastAPI 연결, 실제 retrieval, Codex 호출과 SSE 동작은 별도 live smoke로 검증하고 migration 증거와 구분해 기록한다.
- 실제 데이터와 평가 기준이 마련되면 한국어 retrieval 품질과 성능을 측정하고, 그 전에는 개선을 주장하지 않는다.
