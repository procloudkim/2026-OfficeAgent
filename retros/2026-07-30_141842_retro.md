## KPT 회고

### Keep (좋았던 것)

- V1 기준선을 먼저 검증한 뒤 V2 branch를 생성해 기존 동작과 신규 설계의 증거가 섞이는 위험을 줄였다.
- 저장소 전환 이유를 단순한 기술 선호가 아니라 transaction, backup, health check, credential 경계로 설명해 선택 근거를 추적할 수 있게 했다.
- 구현되지 않은 내용을 `DRAFT`로 표시해 문서 작성만으로 기능과 검증이 완료된 것처럼 보이지 않게 했다.
- Redis나 ANN을 바로 도입하지 않고 측정된 요구가 없는 최적화를 제외해 Phase 2 범위를 통제했다.

### Problem (나빴던 것)

- PostgreSQL·pgvector용 실제 code와 test가 아직 없어 단일 transaction 설계가 동작한다는 증거가 없다.
- SQLite–Chroma의 기존 cross-store 원자성 및 partial failure 위험은 설계상 전환 이유로만 정리됐으며 아직 제거되지 않았다.
- Compose digest 고정, migration 불변성, 실제 PostgreSQL·pgvector runtime version은 검증하지 않았다.
- rollback, concurrency, ingest/query race, identical miss single-flight 동작은 아직 증명되지 않았다.
- 실제 한국어 검색 품질과 citation entailment도 이번 설계 단계에서는 검증하지 않았다.

### Try (개선해야 할 것)

- digest-pinned Compose와 migration runner를 만들고 실행 중인 PostgreSQL·pgvector version을 확인한다.
- unified `CorpusStore`의 rollback 및 concurrency 실패 테스트를 먼저 작성한 뒤 구현한다.
- document, vector, cache invalidation, corpus revision이 동일 transaction에서 함께 commit되거나 rollback되는지 integration test로 검증한다.
- ingest/query race와 identical cache miss 상황을 재현해 일관성 및 single-flight 정책을 확정한다.
- 저장소 전환 이후 별도 평가 자료로 한국어 retrieval 품질과 citation entailment를 검증한다.
