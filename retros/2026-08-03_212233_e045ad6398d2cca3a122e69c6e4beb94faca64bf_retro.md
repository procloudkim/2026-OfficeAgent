## 수행 내용

- 제품 업로드 한도를 테스트용 1 MB가 아닌 설정상의 20 MiB로 바로잡았다.
- 업로드 허용 기준을 파일명 확장자 판정으로 명확히 하고 임베딩 초기화를 지연 로드로 수정했다.
- 문서 갱신이 정규화된 같은 파일명의 재업로드로 이뤄짐을 반영했다.
- 근거 없는 JSON·SSE 결과와 인증·TLS·사용자별 자료 저장소의 부재를 명시했다.
- 일반 질문에서 외부 데이터가 전송되는 경계를 추가했다.
- 실행 수치는 추적 문서가 소유하고 안내 문서는 종료 코드와 참조 위치만 안내하도록 정리했다.

## KPT 회고

### Keep (좋았던 것)

- 설정값과 초기화 동작을 실제 코드와 대조해 테스트용 수치를 제품 동작으로 오인하는 문제를 줄였다.
- 실행 수치의 소유 위치를 추적 문서로 한정해 안내 문서 사이의 중복과 불일치 가능성을 낮췄다.
- 실행 결과의 귀속 범위를 경로 단위로 제한해 문서 전용 변경에서 검증을 과장하지 않았다.

### Problem (나빴던 것)

- 문서 전용 최신 상태에서 모든 실행 구성을 다시 검증한 것은 아니므로 전체 동작의 재검증은 증명되지 않았다.
- 인증·TLS·사용자별 자료 저장소가 없는 상태에서 실제 운영 안전성은 증명되지 않았다.
- 일반 질문의 외부 데이터 전송 경계가 실제 사용 흐름에서 충분히 인지되는지는 확인되지 않았다.

### Try (개선해야 할 것)

- 런타임 기준점과 인계 시점의 경로별 동등성을 다시 확인하고 실행 구성별 검증 결과를 해당 근거에 귀속한다.
- 인증·전송 보호·사용자별 자료 분리 요구사항을 정의하고 각각의 검증 절차를 마련한다.
- 일반 질문 흐름에서 외부 전송 안내가 노출되는 지점을 점검하고 재현 가능한 확인 절차를 추가한다.

## 증거

- 최신 커밋에서 4개 파일이 변경되고 80줄이 추가되며 18줄이 삭제되었다.
- 코드 대조를 통해 제품 설정의 20 MiB 한도, 파일명 확장자 판정, 임베딩 지연 로드가 확인되었다.
- 실행 결과의 귀속은 런타임 기준점과 인계 시점의 경로 한정 동등성으로 구분되었다.

## 직접 보완

> 최종 내용 책임: 지원자 / 사실 대조·초안·문장 정리: Codex 보조

- 초안의 `1,000,000 bytes`는 `tests/helpers.py`의 격리 fixture 값이었고 제품 기본값이
  아니었다. 실제 기본값은 `infrastructure/settings.py`의 20 MiB다. 테스트 설정과
  production setting을 구분하지 않으면 정확한 문장도 잘못된 운영 매뉴얼이 된다.
- 업로드 허용 여부는 `infrastructure/parsers.py`에서 filename 확장자 `.pdf`, `.txt`,
  `.md`로 판단하며 MIME은 저장 metadata일 뿐 허용 gate가 아니다. FastEmbed model도
  startup이 아니라 `embeddings.py::_get_model()`의 첫 embedding에서 lazy load된다.
- PostgreSQL 문서 identity는 경로를 제거한 filename을 NFKC·casefold·공백 정규화한
  값이다. 같은 이름·같은 bytes는 `unchanged`, 같은 이름·다른 bytes는 version이
  증가한 `updated`, 다른 이름은 새 문서가 된다.
- score gate를 통과한 근거가 없으면 `question_answering.py`가 고정 거절 답변과
  `grounded=false`, 빈 citation, `cache_skip_reason=no_evidence`를 반환하며 Codex를
  호출하거나 cache를 쓰지 않는다.
- 이 서버는 로컬 과제용으로 API 인증·TLS·사용자별 corpus가 없다. loopback 밖에
  공개하지 않으며, 일반 질문도 질문과 검색 문맥을 외부 Codex에 보내므로 실제 문서
  사용 전 데이터 전송 승인이 필요하다.
- 배운 점은 매뉴얼의 숫자를 기억으로 쓰지 않고 `제품 기본 설정→실행 경로→test
  override` 순서로 확인해야 한다는 것이다. 구현 품질뿐 아니라 독자가 안전하게
  실행하고 실패를 올바르게 해석할 수 있어야 제출 문서의 신뢰도가 생긴다.
