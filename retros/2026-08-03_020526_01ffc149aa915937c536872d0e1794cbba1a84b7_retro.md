## KPT 회고

### Keep (좋았던 것)

- 기본 바인딩을 로컬로 제한하고 준비 상태 실패 세부를 숨겨 외부 노출 범위를 줄였다.
- 실행 환경과 프롬프트를 허용 목록과 민감 값 검사로 제한해 자격 증명과 환경 정보가 회고 입력에 섞일 가능성을 낮췄다.
- 모델은 구조화된 값만 생성하고 로컬 검사가 형식을 소유하게 해 이전 출력 형식 편차를 통제했다.
- 전용 작업 공간과 일회용 데이터베이스를 사용하고 영수증에서 답변과 연결 정보를 제외해 검증 격리와 증거 최소화를 함께 강화했다.
- 잠금과 복구 기록, 원본 상태 검사를 추가해 관련 없는 인덱스 상태와 사용자 파일을 훼손할 위험을 줄였다.

### Problem (나빴던 것)

- 최종 현재 커밋 기준 실제 Codex HTTP 또는 스트리밍 라이브 스모크가 아직 실행되지 않아 라이브 검증 완료를 주장할 수 없다.
- 클린 체크아웃 재현, 원격 상태 일치, 최종 기록기와 감사 실행이 최종 커밋 뒤로 남아 있다.
- 로컬 검사는 인증 제공자와 명령줄 도구의 인증 경계, 제공자 측 개인정보 보호, 저장소의 운영체제 수준 읽기 격리를 증명하지 못한다.
- 이전 네 차례 Retrobot 실행은 출력 계약 편차로 회고를 게시하지 못했다.

### Try (개선해야 할 것)

- 최종 현재 커밋에서 승인된 샘플 문맥으로 실제 Codex HTTP 또는 스트리밍 라이브 스모크를 실행하고 결과를 기록한다.
- 클린 체크아웃에서 전체 검증을 재실행하고 원격 상태와 최종 커밋의 일치 여부를 확인한다.
- 최종 기록기와 감사 실행을 수행해 코드, 테스트, 문서와 Retrobot 증거가 같은 커밋을 가리키는지 확인한다.
- 구조화 출력과 로컬 렌더링 경계로 Retrobot 최종 게시를 재시도하고 계약 위반 시 게시 없이 실패하도록 확인한다.
- 로컬 검사가 보장하지 못하는 인증과 개인정보 보호 경계를 별도 승인 및 외부 검증 항목으로 유지한다.
