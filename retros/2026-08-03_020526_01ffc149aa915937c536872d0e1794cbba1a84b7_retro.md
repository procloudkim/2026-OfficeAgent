## KPT 회고

### Keep (좋았던 것)

- 기본 바인딩을 로컬로 제한하고 준비 상태 실패 세부를 숨겨 외부 노출 범위를 줄였다.
- 실행 환경과 프롬프트를 허용 목록과 민감 값 검사로 제한해 자격 증명과 환경 정보가 회고 입력에 섞일 가능성을 낮췄다.
- 모델은 구조화된 값만 생성하고 로컬 검사가 형식을 소유하게 해 이전 출력 형식 편차를 통제했다.
- 전용 작업 공간과 일회용 데이터베이스를 사용하고 영수증에서 답변과 연결 정보를 제외해 검증 격리와 증거 최소화를 함께 강화했다.
- 잠금과 복구 기록, 원본 상태 검사를 추가해 관련 없는 인덱스 상태와 사용자 파일을 훼손할 위험을 줄였다.

### Problem (나빴던 것)

- 최종 현재 커밋 기준 실제 Codex HTTP 또는 스트리밍 라이브 스모크가 아직 실행되지 않아 라이브 검증 완료를 주장할 수 없다.
- 클린 체크아웃 재현, 원격 상태 일치, 최종 기록기와 감사 실행이 최종 커밋 뒤로 남아 있다.
- 로컬 검사는 인증 제공자와 명령줄 도구의 인증 경계, 제공자 측 개인정보 보호, 저장소의 운영체제 수준 읽기 격리를 증명하지 못한다.
- 이전 네 차례 Retrobot 실행은 출력 계약 편차로 회고를 게시하지 못했다.

### Try (개선해야 할 것)

- 최종 현재 커밋에서 승인된 샘플 문맥으로 실제 Codex HTTP 또는 스트리밍 라이브 스모크를 실행하고 결과를 기록한다.
- 클린 체크아웃에서 전체 검증을 재실행하고 원격 상태와 최종 커밋의 일치 여부를 확인한다.
- 최종 기록기와 감사 실행을 수행해 코드, 테스트, 문서와 Retrobot 증거가 같은 커밋을 가리키는지 확인한다.
- 구조화 출력과 로컬 렌더링 경계로 Retrobot 최종 게시를 재시도하고 계약 위반 시 게시 없이 실패하도록 확인한다.
- 로컬 검사가 보장하지 못하는 인증과 개인정보 보호 경계를 별도 승인 및 외부 검증 항목으로 유지한다.

## 직접 보완

> 최종 내용 책임: 지원자 / 사실 대조·초안·문장 정리: Codex 보조

- 제품 쪽에서는 API 기본 bind를 loopback으로 제한하고 readiness 응답을 migration
  head와 pgvector version으로 좁혔다. readiness는 DB·schema 준비를 뜻하며 Codex
  로그인이나 실제 답변 품질을 증명하지 않는다는 경계를 유지했다.
- live smoke는 저장소 밖 workspace와 일회용 database를 사용하고, 답변 본문·DB URL·
  경로를 receipt에서 제외했다. Docker test는 Codex·Node·credential과 사용자
  `.codex`가 없는 환경을 검사해 구독 없는 경로와 실제 live 경로를 분리했다.
- Retrobot은 commit 제목·파일명·diff 대신 committed SHA·시각·aggregate shortstat와
  최신 WORKLOG 날짜 구간만 제한 크기로 전달한다. 모델은 구조화 값만 만들고, local
  guard가 검증·Markdown 렌더링을 소유하도록 바꿔 출력 heading 편차를 줄였다.
- 네 차례 publish 실패를 숨기지 않고 contract를 좁혔다. lock, index 보존,
  no-clobber 설치와 recovery journal을 추가해 다른 staged 상태나 사용자 파일을
  자동으로 덮지 않고 애매하면 fail-closed하도록 했다.
- 이 경계는 provider 측 개인정보 보호, 인증 서비스의 동작이나 OS 수준 repository
  read isolation을 증명하지 않는다. 자동화 안전을 위해 Retrobot 자체가 커져 인지
  비용과 commit 잡음이 늘어난 trade-off도 있다.
- 당시 남아 있던 actual Codex/Uvicorn, detached clean launch와 remote parity는 후속
  `11c6cea` bundle에서 확인됐다. 자동 회고 생성은 내 학습 완료 증거가 아니므로
  직접 보완은 별도의 코드 추적과 설명 뒤에 작성한다.
